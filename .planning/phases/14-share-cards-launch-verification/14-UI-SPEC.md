# Phase 14 — UI Design Contract

> Visual and interaction contract for the share cards (1200×630 PNGs rendered with satori + resvg), the static share pages at `/s/...`, and the copy-link wiring on the team page and callout cards. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

All decisions in `14-CONTEXT.md` (D-01..D-26) are locked. This contract fills in the areas CONTEXT left to Claude's discretion: card geometry, sizes, stripe treatment, and whether to extract `CopyLinkButton.svelte`. Everything comes from the Phase 12 system (`12-UI-SPEC.md`, `web/src/app.css`), using **light tokens only** (D-07). Anything not mentioned here stays as Phase 12/13 shipped it.

Scope: `web/` only (`web/scripts/share.mjs`, `web/scripts/og-template.mjs`, `web/src/lib/share.ts`, `CalloutCard.svelte`, `TeamPage.svelte`, and the new `CopyLinkButton.svelte`). Never touch `pipeline/`.

## Design System

| Property | Value |
|----------|-------|
| Tool | none. Svelte 5 + Vite with hand-rolled CSS tokens in `web/src/app.css`. The shadcn gate doesn't apply because this isn't a React project. |
| Preset | not applicable |
| Component library | none |
| Icon library | none. Cards use **no emoji and no icon font**. The only drawn glyph is the arrow (see "Glyph coverage"). |
| Font (site, unchanged) | Inter Variable + IBM Plex Mono 400/600 (Phase 12) |
| Font (cards) | Static WOFF files from `node_modules` (D-03): `@fontsource/inter` `inter-latin-{400,700}-normal.woff` (5.3.0) and `@fontsource/ibm-plex-mono` `ibm-plex-mono-latin-{400,700}-normal.woff` (5.3.0). Registered in satori as `name: 'Inter'` (weights 400/700) and `name: 'IBM Plex Mono'` (weights 400/700), `style: 'normal'`. No WOFF2, no variable font, no system fallback font. |
| Card renderer | satori (exact pin, plain `{type, props}` trees) → `@resvg/resvg-js` (exact pin) → PNG. `fitTo: { mode: 'original' }`, output exactly 1200×630. |
| Card layout engine limits | satori flexbox subset only: **no CSS grid**, every element with more than one child sets `display: 'flex'`, no `gap` shorthand on wrapping text runs (use `gap` only on flex containers; satori supports `gap`), no `box-shadow: inset`, no `color-mix()`, no CSS variables. All colors are literal hex from the `CARD` constant. |

### Card token object (`CARD` in `web/scripts/og-template.mjs`, D-07)

One exported constant. A vitest test parses `app.css` (the light `:root` block) and asserts `CARD.mood[0..6]`, `CARD.bg`, `CARD.text`, `CARD.muted`, `CARD.rule`, `CARD.border` equal the CSS values, so they cannot drift.

```js
export const CARD = {
  w: 1200, h: 630,
  pad: 64,                 // safe margin on all four sides
  stripe: 12,              // band stripe thickness (top edge + score/mood cell left edge)
  bg: '#ffffff',           // --bg (light)
  text: '#222222',         // --text
  muted: '#6b6b6b',        // --text-muted
  rule: '#222222',         // --rule-strong
  border: '#e3e3e3',       // --border (no-band fallback stripe)
  mood: ['#7f1d1d', '#c2410c', '#b7791f', '#8a8d93', '#2f9e8f', '#15803d', '#0b5d3b'], // --mood-0..6 light
  tint: ['#ebdbdb', '#f5e1d8', '#f3eadb', '#ecedee', '#deefed', '#daebe0', '#d8e5e0'], // mood at 16% over #fff (= --cell-tint)
  tintNone: '#fbfbfb',     // --border at 16% over #fff
  chipFallback: '#6b6b6b', // TeamChip .fallback (--text-muted)
  chipOutline: 'rgba(0,0,0,0.18)', // --chip-outline (light)
}
```

`tint[i]` is computed as `255 + 0.16 × (c − 255)` per channel, the same mix as the site's shaded score cell (`color-mix(in srgb, band 16%, #fff)`). The test recomputes and asserts it.

## Spacing Scale

Declared values (multiples of 4). Site tokens are unchanged. Cards use the same scale in raw px, because satori has no CSS variables.

| Token | Value | Site usage (this phase) | Card usage |
|-------|-------|-------------------------|------------|
| xs | 4px | Gap inside CopyLinkButton between the button and the status text on wrap | Name-to-support-line gap |
| sm | 8px | CopyLinkButton row gap | Score-to-caption gap |
| md | 16px | CopyLinkButton column gap (button ↔ status); header row gap above the copy row | Headline-to-detail gap; footer rule padding-top |
| lg | 24px | Share fallback page side padding | Logo-to-name gap (callout); inner padding of score cell and mood strip |
| xl | 32px | — | Gap between major card rows; logo-to-name gap (team) |
| 2xl | 48px | Share fallback page top padding | — |
| 3xl | 64px | — | **Card safe margin (`CARD.pad`) on all four sides** |

Exceptions:
- Card stripe thickness is 12px (the site's 4px `--stripe-width`, scaled ×3 for a 1200px canvas). Multiple of 4.
- Card logo boxes are 144px (team card), 80px (callout card) and the chip fallback is the same box. Multiples of 8.
- Card score cell is 352×192px.
- **Hairline exceptions (stroke widths, not spacing):** the 2px card footer rule (`--rule-strong`, scaled from the site's 1px) and the 2px chip outline (`--chip-outline`) are border thicknesses. They're deliberately not multiples of 4, and they're the only sub-4px values on the cards.
- Copy link button keeps `min-block-size: var(--tap-min)` (44px), as in CalloutCard.

## Typography

### Site (unchanged, used by the new copy button and status)

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`--text-body`) | 400 | 1.5 |
| Label | 14px (`--text-label`) | 400; 700 on the Copy link button | 1.4 |
| Heading | 20px (`--text-heading`) | 700 | 1.25 |
| Display | 28px (`--text-display`) | 700 (the team-page score stays mono 600 (`--weight-semibold`): existing Phase 12 behavior, unchanged and out of scope; the two-weight rule below applies to the PNG cards only) | 1.1 |

### Card type scale (1200×630 canvas): exactly 4 sizes

| Role | Size | Family / weight | Line height (px) | Used for |
|------|------|-----------------|------------------|----------|
| Meta | 24px | IBM Plex Mono 400, UPPERCASE, `letterSpacing: 0.96` (0.04em); or Inter 700 for the site name and type kicker | 32 | Date stamp, type kicker, "out of 100" caption, footer site name + domain |
| Support | 36px | Inter 400 / Inter 700 / IBM Plex Mono 400 | 44 | Rank + record line (mono 400), mood label (Inter 700), callout team name (Inter 700), callout detail (Inter 400) |
| Title | 56px | Inter 700 | 62 (≈1.1) | Team name (team card), callout headline, site-card headline |
| Score | 160px | IBM Plex Mono 700 | 160 (1.0) | The team score only |

Card weights: exactly TWO weights, 400 (regular) and 700 (bold), in both families: Inter 400/700 and IBM Plex Mono 400/700 (four WOFF files). This amends CONTEXT D-03, which originally listed Inter 400/700/800 and IBM Plex Mono 500/600; the change was made after the UI checker's typography gate, and 14-CONTEXT.md is updated to match. Both mono files (`ibm-plex-mono-latin-{400,700}-normal.woff`) were verified present, with the same glyph coverage, on 2026-11-12. The on-site team-page score (IBM Plex Mono 600) is existing Phase 12 behavior and out of scope here. Numbers (score, rank, record, "#", the date's digits inside the mono stamp) are always mono. Words (team names, labels, headlines, detail) are always Inter.

Card text rules:
- **Team names are never truncated** (D-10). They wrap at word boundaries, up to 2 lines at 56px. If the era name is longer than 28 characters (none today; the guard covers future data), drop it to 36px Inter 700. No ellipsis on names.
- **Callout headline:** max 2 lines, ellipsis (D-10). Implement two layers: (1) satori `display: 'block'`, `lineClamp: 2` on the headline element, and (2) a JS pre-clamp `clampText(s, 68)` that cuts at the last word boundary before 68 characters and appends `…` (U+2026, covered by Inter). The fixture "Seahawks fans have been buying the jersey for 1,497 straight days" (65 chars, the longest in all snapshots) must render on 2 lines **with no ellipsis**. A test asserts this by rendering the fixture and checking that `clampText` returned the input unchanged.
- **Callout detail:** max 2 lines, the same two layers with `clampText(s, 110)`.
- **Mood label:** 1 line at 36px Inter 700. The longest label, "It’s fine. Everything’s fine." (29 chars, about 560px), fits the 1072px strip without wrapping. No clamp needed. The curly apostrophe U+2019 is required (do not normalize it to `'`).
- Text color is only `CARD.text` (#222) or `CARD.muted` (#6b6b6b). Mood colors never color text (Phase 12 rule: `--mood-*` are non-text graphics only).

### Glyph coverage (verified against the shipped WOFF files, 2026-11-12)

| Character | Inter latin 400/700 | Plex Mono latin 400/700 | Card handling |
|-----------|------------------------|-------------------------|---------------|
| `’` U+2019, `·` U+00B7, `#`, `–` U+2013, `−` U+2212 (mover headlines "Ravens −25"), `…` U+2026, `+`, `,` | covered | covered | Render as text |
| `→` U+2192 (mover detail "It’s fine. Everything’s fine. → Cautiously smug") | **missing** | **missing** | **Never sent to satori as text.** `cardRuns(text)` splits on `→` and emits an inline SVG arrow element between the text runs (see Callout card). |
| Any emoji (band `emoji` field) | n/a | n/a | Never placed on a card (D-05) |

`share.mjs` runs a coverage guard before rendering. For every string that reaches a card (after `→` is split out), every code point must be in the cmap of the font assigned to that element (read once with satori's font buffers, or with a tiny cmap parse; fontkit is not needed if the test uses a precomputed allow-list). If any code point is missing, **fail the build** with `share: missing glyph U+XXXX in "{text}" ({card path})`. Never render tofu silently. The D-05 vitest renders all 7 band labels and the mover arrow case.

2. The Copy link button focus ring (`:focus-visible` outline)

### Cards (light only, D-07)

| Role | Value | Share of canvas | Usage |
|------|-------|-----------------|-------|
| Dominant (60%) | `CARD.bg` #ffffff | ~75% | Card background |
| Secondary (30%) | `CARD.tint[band]` + `CARD.rule` #222 | ~20% | Score cell fill, mood strip fill, footer rule |
| Accent (10%) | `CARD.mood[band]` | ~5% | **Only** the 12px top stripe, the 12px left edge of the score cell, the 12px left edge of the mood strip (team card), and the 7-segment scale bar (site card) |
| Text | #222 / #6b6b6b | — | All text |

Band resolution: `bandIndex(row.band, meta.bands)` → `moodToken(idx, bands.length)` → `CARD.mood[n]` / `CARD.tint[n]`. That is the same mapping the site uses. If the index is < 0 (unknown band), use `CARD.border` for the stripe and `CARD.tintNone` for the fill, mirroring the site's `var(--border)` fallback.

Contrast (computed): #222 on every tint is ≥ 11.89:1. #6b6b6b on #fff is 5.33:1. Mood stripes vs #fff range from 3.28:1 (mood-4) to 10.02:1 (mood-0), all ≥ 3:1 as graphics.

Logos: drawn unmodified on white (light `--logo-disc` is transparent): no disc, no recolor, no filter, `objectFit: 'contain'` inside the box. Logos are never site branding, so the **site-default card has no logo**.

## Card Geometry: shared frame

Canvas 1200×630, `backgroundColor: #ffffff`, root `display: 'flex', flexDirection: 'column'`, `fontFamily: 'Inter'`.

```
y=0    ┌──────────────────────────────── top stripe 1200×12, CARD.mood[band] ─────────────────────┐
y=12   │                                                                                          │
y=64   │   ┌─ SAFE AREA x 64..1136, y 64..566  (1072 × 502) ─────────────────────────────────┐   │
       │   │  all text, logos, score, mood strip                                               │   │
y=516  │   │  ─────────── footer rule 2px #222 ───────────────────────────────────────────── │   │
y=534  │   │  Feel-Good Score (Inter 700 24 #222)          nfl-team-feelings.vercel.app (mono) │   │
y=566  │   └───────────────────────────────────────────────────────────────────────────────────┘   │
y=630  └──────────────────────────────────────────────────────────────────────────────────────────┘
```

- **Safe area:** padding 64px on all sides → content box x 64–1136, y 64–566 (1072×502). Only the decorative top stripe sits outside it. X and LinkedIn show `summary_large_image` at ≈1.91:1 (1200×628), so nothing load-bearing is lost. Facebook and Slack show the full image. Clients that center-crop harder (iMessage compact bubbles, WhatsApp square thumbnails) lose the outer margin first. The square center (x 285–915) is an accepted lossy case and is not designed for.
- **Main column:** `display: 'flex', flexDirection: 'column', justifyContent: 'space-between', flexGrow: 1`. The body rows stack at the top. The footer is pushed to the bottom of the safe area.
- **Footer** (every card, height 50 = 2px rule + 16 padding + 32 line): `display: 'flex', flexDirection: 'row', justifyContent: 'space-between', alignItems: 'center', borderTop: '2px solid #222', paddingTop: 16`.
  - Left: `Feel-Good Score`, Inter 700 24px, #222. Text wordmark only, never a logo.
  - Right: bare domain = `new URL(resolveSiteOrigin(process.env)).host` (e.g. `nfl-team-feelings.vercel.app`), IBM Plex Mono 400 24px, #6b6b6b, lowercase (no uppercase transform).

## Logo / chip fallback (D-04, mirrors TeamLogo → TeamChip)

Order, per card:
1. If `VITE_LOGOS` is `off` (case-insensitive, the same rule as `logosEnabled`), use the chip.
2. Else, if `web/public/logos/{FR}.png` doesn't exist or can't be read, use the chip and log `share: logo missing for {FR}, using chip` once per franchise.
3. Else, embed the PNG as a base64 data URI. Read each file once and reuse the URI across all cards.

Chip (same box as the logo: 144 team / 80 callout): `display:'flex'`, `borderRadius: 12` (team) / `8` (callout), `backgroundImage: 'linear-gradient(135deg, {primary} 0%, {primary} 50%, {secondary} 50%, {secondary} 100%)'`, `border: '2px solid rgba(0,0,0,0.18)'`. If either color fails `^#[0-9A-Fa-f]{6}$`, use a solid `backgroundColor: '#6b6b6b'` (TeamChip `.fallback`). The chip has no letters on it.

## Share Page Fallback HTML (`dist/s/**/index.html`, D-15/D-17)

The visible body exists only for no-JS visitors and the instant before `location.replace`. It loads no JS bundle, no stylesheet, and no web font: inline styles only, with a system font stack.

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <meta name="color-scheme" content="light">
  <title>{og:title} | Feel-Good Score</title>
  … meta description, og:*, twitter:*, canonical (D-15) …
  <script>location.replace('/' + {JSON-encoded hash, e.g. "#/team/BUF/2026/9"})</script>
</head>
<body style="margin:0;background:#ffffff;color:#222222;font:400 16px/1.5 system-ui,-apple-system,'Segoe UI',Roboto,'Helvetica Neue',Arial,sans-serif">
  <main style="max-width:680px;margin:0 auto;padding:48px 24px">
    <p style="margin:0 0 16px;font-weight:700">Feel-Good Score</p>
    <h1 style="margin:0 0 8px;font-size:28px;line-height:1.1;font-weight:700">{og:title}</h1>
    <p style="margin:0 0 24px;color:#6b6b6b">{og:description}</p>
    <p style="margin:0"><a href="/{hash}" style="color:#1f5fbf">Open {era name} on Feel-Good Score →</a></p>
  </main>
</body>
</html>
```

Rules:
- Every interpolated value goes through `escapeHtml` (`& < > " '`). The hash inside `<script>` is emitted with `JSON.stringify`, and then `<` is escaped as `<`, so a `</script>` in the data can't break out of the tag.
- The link `href` and the redirect are root-relative (`/#/…`), so they work on localhost and preview. `og:url`, `og:image` and `canonical` are absolute on the production origin (D-16).
- Light only (`color-scheme: light`), because the page is a transit page. Colors are the light tokens: bg #fff, text #222, muted #6b6b6b, link #1f5fbf. Spacing 8/16/24/48. Sizes 16 and 28.
- No meta refresh, no emoji, no logo image.

## Copy-Link Interaction Contract (SHARE-03, D-22..D-24)

### Decision: extract `web/src/components/CopyLinkButton.svelte`

Both CalloutCard and the team header use one component, so the WR-05 behavior (clear the live region, then announce; focus the manual field) lives in one place.

Props: `{ getUrl: () => string; name: string; ariaLabel?: string }`.

Markup and behavior (moved verbatim from CalloutCard, logic unchanged):
```
<div class="copy-link">
  <button type="button" class="copy" aria-label={ariaLabel} onclick={copy}>Copy link</button>
  <p class="status" class:visually-hidden={!status} role="status">{status}</p>
  {#if result === 'manual'}<input class="manual" readonly value={url} aria-label="Link to {name}" …select-on-focus/click…>{/if}
</div>
```
- `copy()`: `result = 'idle'` → `await tick()` → `url = getUrl()` → `copyText(url)` → if `'manual'`, `await tick()` and focus the input. The URL is computed **at click time** (it reads `location.origin`).
- `.copy-link`: `display: flex; flex-wrap: wrap; align-items: center; column-gap: var(--space-md); row-gap: var(--space-xs); flex: 1 1 auto; min-width: 0; position: relative`.
- `.copy`: unchanged CalloutCard styles (min-block-size 44px, padding 0 16px, 14px/700, `--accent` text, transparent bg, 1px `--border`, `--radius-md`, accent focus ring).
- `.status`: 14px/1.4 `--text-muted`. It sits to the right of the button when there's room and wraps under it otherwise. It is always in the accessibility tree and visually hidden only while empty.
- `.manual`: `flex-basis: 100%`, the existing styles (44px min height, 1px border, `--radius-sm`).
- CalloutCard's `.actions` keeps `See {name}` as its first child; `<CopyLinkButton>` replaces the old button, status and input. The visible difference: the status now appears beside the button rather than below the actions row. This is accepted.

### States (both placements)

| State | Visible | Live region (`role="status"`) |
|-------|---------|-------------------------------|
| idle | `Copy link` button | empty (visually hidden) |
| copied | button unchanged | `Link copied` |
| manual (clipboard + execCommand both failed) | button + full-width readonly input holding the URL, focused, text selected | `Copy the link below` |
| repeat click | the region clears, then re-announces the same message | (WR-05) |

There is no toast, no icon swap, no timer reset, and no disabled state.

### What gets copied

| Placement | Condition | Copied text |
|-----------|-----------|-------------|
| CalloutCard | `hasSharePage(c.season, c.week, meta)` | `location.origin + calloutSharePath(c)`, e.g. `https://nfl-team-feelings.vercel.app/s/c/2026/9/CLE-worried/` |
| CalloutCard | otherwise (pre-launch week or week not in data) | `deepLink(calloutHref(c))` (unchanged v1 behavior) |
| Team page header | `hasSharePage(season, week, meta)` for the **viewed** (season, week); on the latest view these are `meta.latest` | `location.origin + teamSharePath(FR, season, week)`, e.g. `…/s/team/BUF/2026-w9/`. The URL always pins the week, even from the latest view, because links are durable (D-14) |
| Team page header | otherwise | `deepLink(latest ? teamHash(FR) : teamHash(FR, season, week))` (the same hash the page is on) |

CalloutCard needs `meta` (or a precomputed `share` boolean/URL builder) for `hasSharePage`. Pass it as a prop from `CalloutCards`, which already receives `meta`.

### Team page placement (`TeamPage.svelte` header, loaded-with-row state only)

- Add a new last child of `.who`, after the `odds/qb` sub line: `<div class="share-row"><CopyLinkButton getUrl={…} name={name} ariaLabel="Copy link to {name}" /></div>`.
- `.share-row`: `display: flex; min-width: 0; margin-top: var(--space-xs)`. The button left-aligns under the meta lines in the left header column at every width. At 375px the header grid already drops the score cell below the name block, and the button stays in `.who`, so nothing moves.
- Visible label `Copy link`; accessible name `Copy link to {era name}`. The accessible name contains the visible label (WCAG 2.5.3), and it tells the header button apart from the callout buttons further down the same page.
- Not rendered in the loading, error, or empty (`!row`) states.
- CalloutCard keeps its visible-only label `Copy link` (no aria-label change), since its heading already names the team.
