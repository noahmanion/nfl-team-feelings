# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This is the first frontend phase. It sets up the design system that Phases 3, 4, 6 and 8 extend (see the "Design System for Later Phases" section at the end).
> Mode: autonomous. Every decision below is either locked in 02-CONTEXT.md (marked **[CONTEXT]**) or a researcher default (marked **[default]**). No user questions were asked.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Svelte 5 project; shadcn is React-only and CONTEXT says plain CSS) **[CONTEXT]** |
| Preset | not applicable |
| Component library | none. Hand-written Svelte 5 components with scoped `<style>` blocks **[CONTEXT]** |
| Styling | Global tokens as CSS custom properties in `web/src/app.css`. Component styles are scoped and use only `var(--token)`. Components never contain raw hex, except team colors injected from data through inline custom properties (`style="--team-primary: …"`) **[default]** |
| Icon library | none. The only glyphs are the Unicode arrows ▲ ▼ – and the mood emoji supplied by `meta.json` **[default]** |
| Font | System stack, no web fonts: `system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`. All numbers use `font-variant-numeric: tabular-nums` **[default]** |
| Color scheme | Light and dark, following `prefers-color-scheme`. `:root { color-scheme: light dark; }` so native controls (select, range) pick up the matching theme **[CONTEXT]** |
| Routing | Tiny hash router. `#/` is the latest board and `#/board/{season}/{week}` is a specific week **[CONTEXT]** |

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--space-xs` | 4px | Gap between chip and abbreviation, arrow and delta value, emoji and label |
| `--space-sm` | 8px | Vertical gap between the two lines of a mobile row; gap between rows; gaps inside the controls |
| `--space-md` | 16px | Page side padding at 375px; row inner padding; column gap in desktop rows |
| `--space-lg` | 24px | Space between header, controls and board heading; desktop page side padding |
| `--space-xl` | 32px | Space between board and footer |
| `--space-2xl` | 48px | Top padding of the page header at ≥1024px |
| `--space-3xl` | 64px | Bottom page padding at ≥1024px |

Other fixed sizes (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--radius-sm` | 4px | Team chip, badges |
| `--radius-md` | 8px | Board rows, buttons, select, status panels |
| `--chip-size` | 16px | Team color chip (square) |
| `--stripe-width` | 4px | Mood-band stripe on the left edge of each row |
| `--tap-min` | 44px | Minimum height and width of every interactive control |
| `--content-max` | 960px | Max width of the board column at ≥1024px |

Exceptions: the 44px touch-target minimum (select, Latest button, slider hit area). 44 is a multiple of 4 but not of 8, and it is used on purpose for accessibility.

Breakpoints: the design is mobile-first. The only layout breakpoint is `@media (min-width: 1024px)`. Between 376px and 1023px the mobile layout stretches to `max-width: 640px` and is centered. Nothing scrolls horizontally at 320px and above.

## Typography

Exactly 4 sizes and 2 weights.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Label | 14px | 400 (600 for deltas and column headers) | 1.4 | Record, Elo detail, delta values, column headers, footer stamp, slider tick labels, badges |
| Body | 16px | 400 / 600 | 1.5 | Subhead, team name, mood label, status messages, controls text, wordmark (600) |
| Heading | 20px | 600 | 1.25 | Board heading "2026 · Week 10", status panel titles |
| Display | 28px | 600 | 1.1 | The H1 headline and the score number in each row |

Weights: 400 (regular) and 600 (semibold). No other weights.

Rules:
- Score numbers are integers with `tabular-nums`, right-aligned in their column on desktop. Never show decimals **[CONTEXT]**.
- Abbreviations ("BUF") use Body 16/600 with `letter-spacing: 0.02em`.
- Team full names truncate with an ellipsis on one line (`text-overflow: ellipsis`) and never wrap a row onto a third line.
- Use only the four sizes above. To de-emphasize text, use `--text-muted`, not a smaller size.

| Role | Token | Light | Dark | Usage |

| Border | `--border` | `#DEDED9` | `#30333A` | 1px row borders, select border, slider track (unfilled) |

| Accent (10%) | `--accent` | `#3446D4` | `#8F9CFF` | See reserved list |
| On-accent | `--on-accent` | `#FFFFFF` | `#121316` | Text on accent-filled buttons |
| Up | `--up` | `#18794E` | `#4ADE80` | ▲ score/rank increase (text and arrow) |
| Down | `--down` | `#B42318` | `#FF8A7A` | ▼ score/rank decrease (text and arrow) |
| Destructive | `--danger` | `#B42318` | `#FF8A7A` | Reserved. There are no destructive actions in Phase 2. It shares its value with `--down`, but only the error-panel title icon uses it this phase |

Accent reserved for, and only for:
1. Focus ring (`:focus-visible` outline) on every focusable element
2. Week slider filled track and thumb
3. "Latest" button background (when enabled)
4. Text links (footer "nflverse" link)
5. The "In progress" badge border and text

Accent is never used for score numbers, team names, mood labels, rows, deltas or the headline.

Measured contrast (WCAG 2.x):
- Text: 15.9:1 on `--bg` (light). Muted: 6.1:1 (light) and 7.4:1 (dark). Accent: 6.5:1 / 7.4:1. Up: 5.0:1 / 9.7:1. Down: 6.1:1 / 7.4:1. White on light accent: 7.1:1. Dark text on dark accent: 7.4:1. All text pairs pass AA (4.5:1) at 14px.
- `--border` is decorative. Controls get their 3:1 boundary from the accent/text on the slider thumb and from the select's text and arrow.

### Mood band colors

Seven bands, ordered low to high to match `meta.bands`. The frontend owns these presentation colors as tokens keyed by **band index** (0 = lowest band). Thresholds, labels and emoji always come from `meta.json` **[CONTEXT]**. Colors are used only for **non-text graphics** (the 4px row stripe and the 8px swatch in the legend). They are never used as text color. Every value meets ≥3:1 against `--surface`.

| Index | Band (from meta, for reference only) | Token | Light | Dark |
|-------|--------------------------------------|-------|-------|------|
| 0 | <5 "Witness protection" | `--mood-0` | `#7F1D1D` | `#F87171` |
| 1 | 5–19 "Refreshing mock drafts" | `--mood-1` | `#C2410C` | `#FB923C` |
| 2 | 20–39 "Checking the draft order" | `--mood-2` | `#B7791F` | `#FACC15` |
| 3 | 40–59 "It's fine. Everything's fine." | `--mood-3` | `#8A8D93` | `#8E929A` |
| 4 | 60–79 "Cautiously smug" | `--mood-4` | `#2F9E8F` | `#5EEAD4` |
| 5 | 80–94 "Buying the jersey" | `--mood-5` | `#15803D` | `#4ADE80` |
| 6 | ≥95 "Planning the parade" | `--mood-6` | `#0B5D3B` | `#A7F3D0` |

Resolution rule: a row's stripe color comes from the band whose **label matches the row's `label`**, not from the row's score. Hysteresis can keep a label one band away from where the score sits, and the stripe must match the visible label. If `meta.bands` ever has a different count than 7, map the bands to tokens with `round(i * 6 / (n - 1))`.

Color is never the only signal. The mood is always spelled out in text with its emoji, and deltas always carry ▲/▼/– plus a number.

### Team colors

- Source: `teams/{ABBR}.json` / row data (`nflreadpy.load_teams()` primary and secondary) **[CONTEXT]**. Use color chips only, never logos.
- Render a `TeamChip`: a 16×16px square with `--radius-sm`, filled with `linear-gradient(135deg, var(--team-primary) 0 50%, var(--team-secondary) 50% 100%)`, plus a `box-shadow: inset 0 0 0 1px var(--chip-outline)` where `--chip-outline` is `rgba(0,0,0,.18)` (light) and `rgba(255,255,255,.28)` (dark). The outline keeps navy and black chips visible in dark mode and white halves visible in light mode.
- The chip is `aria-hidden="true"`. The abbreviation and name carry the identity.
- Team colors are never used for text, row backgrounds or borders.

## Layout

### Page structure (top to bottom)

1. `SiteHeader`: wordmark "Feel-Good Score" (Body 16/600, plain text with no link in Phase 2), the H1 headline, and the subhead.
2. `Scrubber`: season select, week slider with its live value, and the Latest button.
3. `BoardHeading`: "2026 · Week 10", an "In progress" badge when it applies, and a muted team count with the score-kind note.
4. `MoodBoard`: an `<ol>` of `BoardRow`s ranked 1..N.
5. `SiteFooter`: last-updated stamp, data-through date, and source.

Rows are **not clickable** in Phase 2: no hover lift and no pointer cursor. The team deep-dive arrives in Phase 4.

## Interaction Contract

### Week scrubber (SITE-04)

- **Season select:** a native `<select>` with a visible `<label>` "Season", options newest first (2026 … 1999) from `meta.seasons`. On change, keep the current week if it exists in the new season, otherwise clamp to that season's max week. Then **assign `location.hash`**, which creates a history entry.
- **Week slider:** a native `<input type="range" min="0" max={maxWeek} step="1">`. `maxWeek` is the season's max week from `meta.seasons`. For the latest season that is `meta.latest.week`, so users can't scrub into unplayed weeks.
  - On `input`: render that week immediately (the season file is already loaded) and update the hash with `history.replaceState`, so dragging doesn't flood the history stack.
  - `aria-valuetext` is the human label ("Preseason", "Week 10", "Wild Card", …). The adjacent `<output for=…>` shows the same label at Body 16/600.
  - Tick labels under the track show only the first label ("Pre"), the last regular-season week ("Wk 17"/"Wk 18") and the last available week ("SB" or the latest week). They are not rendered per week.
- **Week labels:**
  - Week 0 shows "Preseason" (tick "Pre").
  - Weeks 1..R show "Week N" (tick "Wk N"). R is the regular-season week count: 17 for 1999–2020 and 18 for 2021+.
  - Week R+1 shows "Wild Card", R+2 "Divisional", R+3 "Conference Championships" (tick "Conf"), and R+4 "Super Bowl" (tick "SB").
  - **Planner dependency:** CONTEXT says postseason labels come from `game_type`, not raw week numbers. `meta.seasons[]` entries must therefore include `reg_weeks` (or an explicit `week_labels` map), and the frontend must not hardcode the 2021 cutover.
- **Latest button:** visible text "Latest", `aria-label="Jump to the latest week"`. It sets `location.hash = "#/"`. When the current view already is the latest, it is `disabled`: `--border` background, `--text-muted` text, `cursor: default`.
- **Keyboard:** the native range keys are kept and must not be overridden. ←/↓ moves back one week and →/↑ forward one week. Home goes to Preseason and End to the last available week. PageUp/PageDown use the browser default step. Tab order is Season select, then slider, then Latest. No custom key handlers are added to the page.
- **Pointer:** the slider's hit area is ≥44px tall (pad the input with `block-size: 44px`). The thumb is 20px, accent-filled, with a 2px `--surface` ring. The track is 4px: accent fill to the left of the thumb, `--border` to the right. Styling uses `accent-color: var(--accent)` as the baseline. Optional `::-webkit-slider-thumb`/`::-moz-range-thumb` styling may follow the same values.

### Hash routing

| Hash | View |
|------|------|
| `#/` or empty | Latest board (`latest.json`). The heading shows the actual season and week |
| `#/board/{season}/{week}` | That season and week from `snapshots/{season}.json` |
| anything else | Treat as `#/` and replace the hash with `history.replaceState` |

- Invalid season (not in `meta.seasons`) or a week above that season's max: show the latest board, replace the hash with `#/`, and show the Notice (see Copywriting).
- When `#/board/{s}/{w}` equals `meta.latest`, render it the same as `#/`, with the Latest button disabled. Don't rewrite the hash.
- `hashchange` drives all rendering, and the controls reflect the parsed route (single source of truth).

### Data loading

- On boot, fetch `meta.json` and `latest.json` in parallel. Season files are fetched on demand and cached in memory for the session.
- Changing the season while a fetch is in flight renders only the last requested season (ignore stale responses).

### Motion

- No reorder or row animations in Phase 2. The board re-renders in place.
- The only transition is `background-color`/`color` 120ms ease on buttons. It is disabled under `@media (prefers-reduced-motion: reduce)` (`transition: none`).
- No skeleton shimmer. The loading skeleton is static.

## States

| State | Trigger | What renders |
|-------|---------|--------------|
| Loading (initial) | `meta.json`/`latest.json` pending | Header renders immediately. The Scrubber is disabled (controls `disabled`). Board area shows 8 static skeleton rows (`--border` filled 16px bars inside 64px-tall surface rows) with `aria-busy="true"` on the board and a visually hidden "Loading the mood board…" |
| Loading (season switch) | Season file pending | The current board stays visible at `opacity: 0.6` with `aria-busy="true"`. The heading already shows the new season/week. No spinner |
| Fatal error | `meta.json` or `latest.json` fails (network/404/parse) | Scrubber and board are replaced by an error panel (surface, radius 8, pad 24): title, body, and a "Try again" button (secondary style: `--surface` bg, `--border` border, `--text` text, 44px) that re-runs boot. The footer is hidden |
| Season error | `snapshots/{season}.json` fails | Inline error panel in place of the board, with "Try again" and "Go to latest" buttons. The Scrubber stays usable |
| Notice (bad link) | Invalid season/week in the hash | Latest board, plus a dismissible notice line above the BoardHeading (Body 16, `--text-muted`, `role="status"`) and an "×" dismiss button (44px, `aria-label="Dismiss"`) |
| Partial week | `meta.partial_week` true and viewing the latest week | "In progress" badge next to the week in both the Scrubber output and the BoardHeading. A muted note under the heading. Rows for teams that haven't played this week show their previous score with delta "–" |
| Preseason (week 0) | week = 0 | Heading "2026 · Preseason". Records show "0-0". Every delta shows "–" (muted), with screen-reader text "no change, preseason". Muted note under the heading. No rank delta |
| Fewer than 32 teams | Seasons 1999–2001 (31 franchises) | Show the rows that exist. The count line reads "31 teams" (derived from row count, not hardcoded) |
| Empty week | Week array exists but has 0 rows (shouldn't happen) | Empty-state panel (see Copywriting) with a "Go to latest" button |
| Ties | `ties > 0` | Record shows "W-L-T" (e.g. "7-2-1"). Otherwise "W-L" |
| Missing team colors | Color null/invalid | The chip falls back to `--text-muted` for both halves |
| Missing Elo/delta | Field null | Show "–" in `--text-muted`. Never "NaN" or "null" |

Delta formatting:
- `score_delta > 0` renders "▲ 4" in `--up`. `< 0` renders "▼ 7" in `--down` (absolute value after the arrow). `0` or null renders "–" in `--text-muted`.
- Rank delta (desktop second line): "#▲2" / "#▼1" / "#–". A positive `rank_delta` means the team moved **up** the board. The pipeline sign convention must match: rank_delta = previous rank − current rank.

## Accessibility

- **Landmarks:** `<header>`, `<main>`, `<footer>`. The Scrubber is a `<form role="search" aria-label="Choose season and week">` with `submit` prevented. There is one `<h1>` (the headline). The BoardHeading is an `<h2>`.
- **Board semantics:** `<ol aria-labelledby="board-heading">`. Each `<li>` has a visually hidden sentence that comes first in reading order, and the visual cells are `aria-hidden="true"`, so screen readers get one clean line per team:
  `"1. Buffalo Bills, 8 and 1. Score 91, Buying the jersey. Up 4 points, up 2 spots from last week."`
  For preseason: `"… Score 54, It’s fine. Everything’s fine. No change, preseason."` For no change: `"No change from last week."`
- **Contrast:** every text/background pair in the token tables meets ≥4.5:1 in both themes (measured values are in Color). Mood stripes, chip outlines and the slider thumb meet ≥3:1 as non-text graphics.
- **Focus:** `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }` on select, range, and all buttons. Never `outline: none` without this replacement. Rows aren't focusable in Phase 2.
- **Slider:** native range, labelled with `<label for>`, `aria-valuetext` set to the human week label. Keyboard behavior is in Interaction Contract. Don't add an `aria-live` region to the board, because dragging would announce 20+ updates. The slider's own value text is announced natively.
- **Status messages:** the bad-link notice and the season error use `role="status"`. The fatal error panel uses `role="alert"`. After the bad-link redirect, focus stays where it was.
- **Emoji:** `<span aria-hidden="true">{emoji}</span>`. The label text carries the meaning.
- **Touch targets:** ≥44×44px for select, slider hit area, Latest, Try again, Go to latest, and Dismiss.
- **Reduced motion:** honored (see Motion). Nothing animates by default except 120ms button color fades.
- **Zoom:** layout holds at 200% zoom. Rows reflow and nothing gets clipped (the name and label ellipsize; the full text is in the visually hidden sentence).
- **Language:** `<html lang="en">`.

## Design System for Later Phases

> **Informational — NOT Phase 2 scope.** Binding guidance for Phases 3–8; the Phase 2 planner must not build these.

These rules are binding on Phases 3, 4, 6 and 8 so the site stays one coherent system. Later UI-SPECs may add tokens but must not redefine the ones above.

1. **Tokens are the only source of style.** New components use `var(--space-*)`, the four type sizes, two weights, and the color tokens. If a phase needs a new token, add it to `app.css` under a section labelled with that phase.
2. **Navigation (Phase 3+):** when a second view exists, `SiteHeader` gets a nav row: "Board · History · Records · How it works" (Body 16). The current page has a 2px `--accent` underline and `aria-current="page"`. Nav links are text color, not accent, except the active underline.
3. **Charts (Phase 3, 4, 6, Observable Plot):**
   - Chart text uses Label 14 in `--text-muted`, and axis lines and gridlines use `--border`. Plot `style` reads the CSS variables, so charts follow dark mode.
   - The y-axis is fixed at 0–100 for every score chart **[REQUIREMENTS SITE-03]**.
   - Mood bands show as horizontal background bands using `--mood-N` at 10% opacity (light) / 14% (dark), with band labels at the right edge in Label 14 muted.
   - "Spaghetti" (all teams) lines use `--text-muted` at 25% opacity, 1px. The highlighted team uses its `--team-primary` at 2.5px. If that color's contrast against `--bg` is under 3:1 (computed at runtime), fall back to `--team-secondary`, then to `--text`.
   - Season boundaries are a 1px dashed `--border` rule. The line breaks there (no connecting segment).
   - Tooltips (`tip` mark) use `--surface` background, `--border` border, Body 16 text. Charts must not depend on hover: each one has a visible summary line or a table fallback.
4. **Factor breakdown (Phase 4):** diverging horizontal bars centered on the league average. Positive contributions use `--up`, negative use `--down`, sorted by absolute size. Show the top 4, and collapse the rest under a `<details>` "All factors". Each bar's value is in score points (integer) with an explicit sign.
5. **Team page (Phase 4):** route `#/team/{ABBR}` (latest) and `#/team/{ABBR}/{season}/{week}`. `BoardRow` becomes an `<a>` covering the whole row, with a `--bg` hover background and the accent focus ring on the row. Header: TeamChip at 24px (an allowed size variant), team name in Display 28, score in Display 28, MoodLabel in Heading 20.
6. **Callout cards (Phase 8):** `--surface`, radius 8, 16px padding, with a 4px left stripe in the relevant `--mood-N`. Layout: headline sentence (Body 16/600), supporting line (Body 16 muted), and a deep-link "See {Team}" (accent link). On mobile they stack. On desktop they sit in a 3-column grid with a 16px gap above the board.
7. **My-team pin (Phase 8):** the pinned row gets a "My team" Badge (neutral variant: `--border` border, `--text` text) and a `--bg`-to-`--surface` emphasis: `background: color-mix(in srgb, var(--accent) 6%, var(--surface))`. That is the one sanctioned accent tint, and it doesn't change the mood stripe. The pin toggle is an icon button "☆/★" with `aria-pressed`, 44px. Pinning **does not reorder** the ranked list. An optional "Show my team first" can come later.
8. **Prose pages (Phase 6 methodology, Phase 8 records):** reading column `max-width: 680px`. h2 in Heading 20, body in Body 16 at 1.5. Tables use the same row style as the board (surface rows, 8px gap) instead of a striped table.
9. **Biggest movers strip (Phase 8):** reuses `Delta` and `TeamChip`. Horizontal scroll is **not** allowed. On mobile it stacks in two columns (Risers / Fallers).
10. **No logos, no decimals, no new fonts, no new weights** across all phases.
